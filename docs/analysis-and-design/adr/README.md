# Architecture Decision Records (ADRs)

Record architectural decisions that outlive a single PR (tech stack commitments, data model boundaries, authentication adapters, rendering pipeline isolation, storage backend).

## Naming & Format

Name files `NNNN-short-kebab-title.md` (e.g., `0001-technology-stack.md`). Keep each ADR concise:

- **Status**: Proposed | Accepted | Superseded
- **Date / Deciders**
- **Context**: Problem statement + links to Vision / UC / `MISSING_CONTEXT.md`
- **Decision**: What was chosen, alternatives rejected, and trade-offs
- **Consequences**: Impact on code, tests, and operations
